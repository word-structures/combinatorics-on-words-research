# PAPER4_MACRO_RECORD_HUNTER_PROTOTYPE_REPORT_2026-08-29

## Objective
Evaluate whether Paper 4's 19 support families can serve as a constraint compiler for block synthesis, where basic variables are uniform blocks and their Parikh profiles.

## Analysis
In block synthesis, we treat the infinite word as a sequence of blocks of length L.
1. Generating all valid blocks of length L (e.g. L=5) yields a finite macro-alphabet (e.g. 126 blocks).
2. A macro-DFS tries to concatenate these blocks.
3. Paper 4's exact theory says that any abelian square of half-length K >= 2L corresponds to one of the 19 support families.
4. Thus, instead of running an explicit string-comparison for all possible abelian squares at all lengths, the search only needs to:
   a) Explicitly verify short abelian squares (K < 2L) near the boundary.
   b) Verify that the block Parikh profiles do not satisfy any of the affine constraints generated by the 19 families for any K >= 2L.

## Prototype Evaluation
If we map this to a constraint solver (or block DFS), the number of checks required for macro-squares changes from O(|word|^2) string comparisons to evaluating a set of prefix-sum integer equations. 
However, for small L (like L=5), K >= 2L means squares of length >= 10. The 19 families assume a sequence of carry roles. Without a predetermined morphism to fix the roles, the sequence of carries depends on the exact abelian square length K being checked. Because K is arbitrary, the role sequence can be anything, meaning we still have to check all possible K >= 2L. 

## Verdict
**MACRO-SYNTHESIS IS A REFORMULATION, BUT K REMAINS FREE.**
Paper 4's equations are extremely powerful if the macro-sequence (roles) is known. But if we are searching for an arbitrary record word without assuming a specific morphism, the cutpoints 	_i and the roles c_i depend entirely on the choice of K. Since the search must avoid squares for ALL K, we still have to test every possible length K. Evaluating the 19-family equations for every K is computationally equivalent to (or slower than) computing the Parikh vectors directly. 
Thus, Paper 4's constraints are useful for block synthesis ONLY IF we also restrict the search to a specific morphism or role-sequence (i.e. Structure Discovery).
